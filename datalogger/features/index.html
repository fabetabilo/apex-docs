Features

What's included

Apex Datalogger logs data the same way a real datalogger in motorsports would, but instead of writing to an SD card, the sim telemetry is saved stint by stint directly to your PC's file system in a dedicated folder inside the app directory apps/lua/apex/laps/.

  • Fully automatic: install once and let it run in the background.
  • Stint-based logging: each stint is saved as a single CSV file, with timestamps, automatic detection of invalid stints. Data is written to disk every second, so a game crash loses at most the last second.
  • Stint export: every stint carries a JSON log per stint with its session details, lap times and lap markers.
  • Local logging & live streaming: capture telemetry locally, stream it live over UDP, or run both at the same time, each mode works independently.
  • LOG mode: for saving stints locally.
  • TX mode: for transmitting telemetry over UDP to a specific IP and port.
  • Single-logic channel selection: choose which channel groups to log or stream.
  • Performance design: unselected channel groups are never read, keeping overhead low no matter how many channels are available.

  • 180+ channels across 12 groups:

    A more in-depth list of the channels can be found in the section below

    • session — track and weather conditions, real-time session data.
    • car_info — car status, fuel, electronics, temperatures, damage, driving modes, race position, sector times.
    • tires — tire temperatures, pressures, and surface wear.
    • dyn — vehicle dynamics, speed, drivetrain torque and power, wheels-off-track count.
    • ext_elec (extended electronics) — hybrid and prototype/open-wheel electronics (LMP1, LMH, F1), including DRS and ERS/KERS support.
    • aero — aerodynamic forces and drag, including per-wing aero load.
    • sim_info — force feedback, simulator FPS, physics rate, CPU time.
    • input — driver inputs: RPM, clutch, throttle, brake, TC/ABS/TC2 modes, lap times, brake torque.
    • gps — car position, pitch/roll/yaw rates and angles.
    • tires_dyn — tire dynamics: forces, slip, loads, wheel speeds.
    • gforce — G-forces.
    • susp— full suspension geometry: ride heights, CG height, suspension travel, damper data, camber, toe, caster.

  • Extended Control app integration: map buttons to toggle LOG and TX modes on and off.

  • Built-in console: shows live datalogger status and a running log of completed laps, including lap time, outlap flag, and invalid-lap flag.
  • Session mode support: Hotlap, Practice, and Race are supported; other modes are untested.
  • Two app windows:
    • Apex Settings — configure channel groups, modes, and export options.
    • Apex HUD — a simple, at-a-glance display of what the app is doing, with two indicators showing the current LOG and TX status.

Logger Limitations

Please note the following app limitations:

  • The app does NOT log or send live telemetry for other AI cars.
  • The app does NOT log or send live telemetry other online cars in servers.

Channels

Channels are organised into groups, and each group is recorded at its own sampling rate in Hz. This keeps the log small and the logger light: values that change slowly, such as weather or fuel level, don't need to be sampled as often as values that are critical, such as throttle, brake, laptimes or tyre forces. Only the groups that need high resolution are recorded at a high rate.

aero · Aerodynamics

Rate: 10 Hz

Aerodynamic drag and front and rear downforce. Depending on the car, the value comes from the CSP aeromap via the Python app, from an estimate (45/55 split) or from calculating it from the car’s wings. If no data is available, it stays at 0.

Channel Source Description Unit
aerodrag Aero module Aerodynamic drag force N*
aeroDownforceFront Aero module Front downforce N*
aeroDownforceRear Aero module Rear downforce N*
